# Real-data validation

Generated by `tests/TS4Tools.Wrappers.Tests/RealData` (`RealDataValidationTests.Summary_WritesReport`).
Every resource type with a registered wrapper is parsed from real game and mod packages and
serialized back; the output must be byte-identical to the decompressed original. Regenerate with

```bash
TS4TOOLS_REALDATA_WRITE_DOCS=1 dotnet test tests/TS4Tools.Wrappers.Tests --filter FullyQualifiedName~RealData
```

Sample cap: none (full run) resources per type per package 
(`TS4TOOLS_REALDATA_CAP`, 0 = all).

Columns: *present* = resources of the type in the scanned packages; *sampled* = parsed;
*read* = decompression failures; *parse*/*write* = exceptions; *empty* = zero-length resources (not checked); *unsupp.* = versions newer than any legacy
layout, refused by the wrapper (see below); *mismatch* = output differs from the
original (*stable* = of those, how many re-parse to identical output); *fail* = what the family tests assert to be 0.

## Documented legacy limitations

Inherited legacy behaviour (column *legacy*: resources equal to legacy's predicted rewrite / accepted
legacy failures). Accepted mismatches must still be re-parse stable:

- RCOL family, single-chunk resources: legacy always recomputes the one index entry as Position = 0x2C + externalCount * 16, Length = rest of the stream, and replaces a chunk TGI type of 0 with the type for the chunk's tag (`GenericRCOLResource.cs` lines 84-94), then writes those values (UnParse, line 118 ff.). The harness applies exactly these changes to the original before comparing (every standalone GEOM has type 0; some mod BONDs store a short length).
- `0x033260E3`: TkMk (`RCOLResources.txt`): the 18 resources of this type in ClientFullBuild0 are not RCOL data (they start with 0x6A10BC4A and contain no TkMk tag). Legacy `GenericRCOLResource.cs` lines 75-80 fails the same way (negative/huge chunk count); parse failures of this type are accepted.
